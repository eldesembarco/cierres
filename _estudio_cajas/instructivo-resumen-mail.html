Consolidado diario de Mercado Pago por mail

Cada mañana sale automáticamente un mail con el consolidado de Liberaciones de Mercado Pago del día: un solo Excel con todos los locales y todas las operaciones (hoja Detalle operación por operación + hoja Resumen por local). La app arma todo sola — incluso lee los reportes crudos del SFTP directamente. En n8n solo hay que disparar y enviar.

1

Cómo encaja

GET /api/mp/resumen
  → la app lee TODOS los reportes del SFTP, filtra el día objetivo y consolida
  → devuelve el asunto + el cuerpo del mail + el Excel adjunto (base64)
n8n  ──►  arma el mail con eso  ──►  ✉ destinatario

Este flujo es independiente de la ingesta a la base: la app lee el SFTP por su cuenta (usuario read-only), así que n8n no necesita tocar archivos ni SFTP. Solo hacen falta 3 nodos + un disparador.

2

El endpoint que llama n8n

Método / URLGET https://cierres-seven.vercel.app/api/mp/resumen
Headerx-ingest-secret: <el mismo secreto que ya usás para /api/mp/ingest>
Query (opcional)?fecha=YYYY-MM-DD — si no la mandás, usa ayer en hora Argentina. Normalmente: dejarla vacía.
RespuestaJSON con todo lo necesario para el mail (ver abajo).

La respuesta trae:

asuntoAsunto sugerido, ej. “Liberaciones Mercado Pago — 29/06/2026 — 288 operaciones · 14 locales”.
cuerpoHtmlEl cuerpo del mail ya armado y con estilo (resumen por local + totales). Va tal cual en el campo HTML del mail.
archivoNombreNombre del adjunto, ej. MP Liberaciones 2026-06-29 - COMPLETO (todos los locales).xlsx.
archivoBase64El Excel (Detalle + Resumen por local) en base64 — se convierte a binario para adjuntarlo.
totalOperaciones · locales · resumen · totalLos números (por si querés usarlos en el flujo). hayDatos:false si ese día todavía no llegó nada.
3

El flujo en n8n (1 disparador + 3 nodos)

Disparador Schedule Trigger

  • Todos los días a la mañana, ej. 08:00 (zona horaria America/Argentina/Buenos_Aires).

Nodo A HTTP Request — traer el consolidado

  • Method: GET · URL: https://cierres-seven.vercel.app/api/mp/resumen
  • Headers: agregá x-ingest-secret = el secreto de siempre.
  • Response Format: JSON. (Sin fecha usa ayer; para un día puntual: Query param fecha = YYYY-MM-DD.)

Nodo B Convert to File — base64 → adjunto

  • Nodo “Convert to File”, operación “Move Base64 String to File”.
  • Base64 Input Field: archivoBase64
  • Put Output in Field (binary): data · File Name: ={{ $json.archivoNombre }}
  • MIME: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet

(En versiones viejas de n8n es el nodo “Move Binary Data”, modo JSON→Binary, con la misma idea.)

Nodo C Send Email — enviar

  • To: <destinatario puntual — lo define Pablo>
  • Subject: ={{ $json.asunto }}
  • Email Format: HTML · HTML: ={{ $json.cuerpoHtml }}
  • Attachments (binary property): data (el del Nodo B)

Usá la credencial SMTP / cuenta de mail que ya tenés configurada en n8n.

4

Prueba rápida

Para validar sin esperar a la mañana, apuntá el Nodo A a un día con datos, ej. ?fecha=2026-06-29. Debería devolver ok:true, hayDatos:true. Respuesta real de ese día:

GET /api/mp/resumen?fecha=2026-06-29
→ { "ok": true, "fecha": "2026-06-29", "hayDatos": true,
    "archivosLeidos": 33, "totalOperaciones": 288, "locales": 14,
    "asunto": "Liberaciones Mercado Pago — 29/06/2026 — 288 operaciones · 14 locales",
    "archivoNombre": "MP Liberaciones 2026-06-29 - COMPLETO (todos los locales).xlsx",
    "cuerpoHtml": "…", "archivoBase64": "UEsDBB…" }
Listo del lado de la app: el endpoint está deployado y probado en producción (lee el SFTP, consolida y devuelve el Excel). Solo faltan estos nodos en n8n y el mail del destinatario.
5

Notas

  • El Excel es el consolidado crudo de Liberaciones: incluye todos los tipos de operación (pagos aprobados, devoluciones, reclamos, envíos y retiros/PAYOUTS). Las comisiones y los retiros figuran en negativo.
  • Los reportes de MP llegan con demora variable por cuenta: el mail de la mañana es una foto “hasta ahora”. Si un local todavía no reportó, aparece cuando llegue su archivo (al reejecutar el endpoint se recalcula).
  • La app junta las operaciones del día objetivo de todos los reportes (settlement diario del día siguiente + stragglers posteriores) y deduplica filas repetidas, así no se cuenta nada dos veces aunque un reporte se pullee más de una vez.
  • Si hayDatos:false (no llegó nada ese día), podés saltear el envío con un IF, o mandarlo igual (sale vacío).
  • Todo con el mismo secreto x-ingest-secret que /api/mp/ingest: no hay nada nuevo que configurar del lado de n8n.
